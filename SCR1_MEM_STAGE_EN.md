# SCR1_MEM_STAGE_EN

При включении макроса `SCR1_MEM_STAGE_EN` в конвейер SCR1 добавляется отдельная стадия **MEM** между EXU и LSU.

Было:

```text
IFU → IDU → EXU → LSU
```

Стало:

```text
IFU → IDU → EXU → MEM → LSU
```

Основная цель изменения - разорвать длинный комбинационный тракт через EXU/LSU и создать возможность перекрытия выполнения memory-инструкции с последующими независимыми ALU-инструкциями.

Все изменения данной оптимизации защищены макросом `SCR1_MEM_STAGE_EN`.

## MEM stage

После вычисления адреса в EXU инструкция LOAD/STORE передаётся в MEM.

В MEM сохраняются:

```text
LSU command
address
store data
rd
rd write enable
PC
```

После передачи инструкции в MEM EXU может освободиться и принять следующую инструкцию.

```text
EXU → MEM registers → LSU
```

При этом PC и адрес memory operation сохраняются до завершения операции, что позволяет корректно обрабатывать memory exceptions.

## WB buffer

Для независимых ALU-инструкций дополнительно используется однозаписный WB-буфер:

```systemverilog
wb_vd_ff
wb_rd_addr_ff
wb_rd_data_ff
wb_pc_ff
```

Он нужен для ситуации:

```text
MEM : LOAD
EXU : ADD
```

Если LOAD ещё не завершён, результат ADD сохраняется в WB:

```text
MEM : LOAD
WB  : ADD
EXU : следующая инструкция
```

Таким образом EXU не блокируется до завершения старой memory-инструкции.

WB используется только для простых инструкций без побочных эффектов.

## Зависимости и порядок выполнения

Добавлена проверка RAW-зависимостей от:

```text
незавершённого LOAD в MEM;
результата, находящегося в WB.
```

При наличии зависимости младшая инструкция останавливается.

MEM-инструкция считается более старой, поэтому её exception и результат имеют приоритет перед младшими инструкциями.

При exception в MEM младший WB-result сбрасывается и не записывается в архитектурное состояние.

## Запись в MPRF

Так как порт записи MPRF один, используется приоритет:

```text
1. завершившийся LOAD
2. WB
3. обычный EXU writeback
```

Это сохраняет правильный порядок обновления регистров.

## Результат

Модификация позволяет выполнять, например:

```text
MEM : instruction N
WB  : instruction N+1
EXU : instruction N+2
```

вместо ожидания завершения memory operation внутри EXU.

В CoreMark переход от консервативной схемы к реальному overlap дал:

```text
5436 → 5404 cycles
```

Главная цель MEM-stage при этом - не только уменьшение CPI, но и разбиение критического пути для потенциального повышения Fmax.

Post-route анализ показал, что старый критический путь через LSU/memory subsystem перестал быть критическим. После этого проявился новый путь через управляющую логику EXU/WB → EARLY_BRANCH → IFU, который является следующим объектом timing-оптимизации.

Модификация не изменяет ISA и может использоваться совместно с `SCR1_EARLY_BRANCH`.
